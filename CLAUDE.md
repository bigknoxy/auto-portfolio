# Auto-Portfolio — Claude Code Project Instructions

## Project Overview
Two-runtime project: Python scanner generates JSON → Astro static site consumes it.
Python 3.12 + uv for backend. Node 20 + Astro 4 + Tailwind 3 for frontend.

## Before Starting
1. Read `AGENTS.md` — two-runtime architecture, common mistakes.
2. Read `TASKS.md` — complete task list (001-016).
3. Read `IMPLEMENTATION.md` — scanner API, site generation, CI details.

## File Structure Rules

```
cmd/                  — Python CLI (typer)
core/                 — Python scanner logic
  repo_scanner.py     — git repo scanning + caching
  tech_detector.py    — manifest parsing
  description_gen.py  — README/LLM description
  site_generator.py   — writes site/src/data/
  config.py           — config dataclasses
data/
  models.py           — Pydantic ProjectRecord
deploy/               — deployment scripts
site/                 — Astro project (do not add Python here)
  src/components/     — .astro components
  src/layouts/        — page layouts
  src/pages/          — page routes
  src/data/           — JSON data (generated by Python)
  public/previews/    — screenshots
tests/unit/           — pytest unit tests
tests/integration/    — pytest integration tests
tests/fixtures/       — pre-committed git repos for testing
```

## Data Contract (DO NOT BREAK)

The JSON schema in `site/src/data/projects.json` must match `data/models.py`.
If you add a field to `ProjectRecord.to_json_dict()`, also add it to the Astro component.
Required fields: `id`, `name`, `slug`, `total_commits`, `stack`, `quality_score`.

## Cache Protocol

- Cache path: `~/.cache/auto-portfolio/<repo-id>/<head-sha>.json`
- Always pass `use_cache=False` in tests
- Do not cache data with random elements (timestamps are OK, random UUIDs are not)

## Testing Rules

- `tests/fixtures/sample_repo` and `tests/fixtures/backend_repo` are git repos
- `conftest.py` creates them automatically if missing (`pytest_configure` hook)
- Always pass `use_cache=False` to scanner functions in tests
- Do not test Playwright screenshot capture in unit tests (it's optional and slow)
- The Astro build test (`test_generate_site.py`) writes to `tmp_path`, not `site/src/data/`

## Learnings Protocol

echo "## Completed: TASK-NNN — $(date +%Y-%m-%d)" >> LEARNINGS.md

## Do NOT

- Import Python from Astro `.astro` files
- Write to `site/src/data/` during tests (use `tmp_path`)
- Use `gitpython` object model for bulk operations (use subprocess instead)
- Hardcode paths like `/Users/Joshua.Knox`
- Add `node_modules/` or `site/dist/` to version control
- Break the `id` or `slug` stability guarantee (see IMPLEMENTATION.md)
